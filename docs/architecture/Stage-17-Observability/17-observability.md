## 0. Scope
Logging, tracing, metrics, dashboards, alerting + SLOs, cost telemetry, LLM telemetry (tokens, latency, quality, safety), client (web/Android) telemetry, audit logging, on-call/incident tooling, and the privacy rules for all telemetry. Builds on the already-locked rules: one trace_id per turn, usage ledger per model call, config-version stamp, validation_result rows, ids-only logs, Cloud Logging defaults in asia-south1, Error Reporting global (no PII), uptime ≥3 regions, Vertex request-response logging OFF.

Two corrections from research that change earlier assumptions:
1. **Cloud Monitoring is a global service but time-series storage follows the monitored resource's location** – custom metrics written against `global` or against Vertex GLOBAL endpoint resources have **unspecified storage location** (C10). Earlier stages implicitly treated Monitoring as "metadata, no residency issue"; now the rule is: custom metrics must be written against a **regional resource (asia-south1)** and must carry no personal data.
2. **Monitoring alert billing starts no sooner than 1 Sept 2027** ($0.35/metric reference/month); nothing to budget for alerts in Stage 18 for year 1 (C2).
